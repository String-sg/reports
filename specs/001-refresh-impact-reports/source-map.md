## Planning implications

1. Daily adapters should emit typed aggregate facts with source revision, cutoff, method, identity unit and coverage status. They should not copy operational admin responses into public output.
2. Product users can be deduplicated across products only where an explicit stable String ID link or controlled verified identity mapping exists. Keep anonymous browser/session counts outside that total and show coverage plainly.
3. Event participants stay separate. Preserve source-event identity and actual attendance evidence; member-only attendance imports are not complete event coverage.
4. Frozen historical aggregate counts remain labeled historical until approved retained evidence permits deduplication. No sum, hash or estimate can recover unknown overlap from totals alone.
5. Daily auto-publication preserves the last accepted snapshot and holds a new candidate if an enabled required source fails or has anomalies/schema/coverage changes. Keep check/coverage dates visible without a public stale indicator. Historical baseline acceptance awaits Kah How's verification, including past figures absent from the current site.

No production mappings were inferred from shared domain names alone; entries explicitly marked candidate/unknown need deployment or source-owner confirmation during implementation discovery.
